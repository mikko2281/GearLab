# GearLab 6.4.1 — проверка производительности

Дата: 7 ноября 2026 года. Сравнение с поведением 6.4.0 на одном компьютере (MIKO, 12 логических процессоров, .NET Framework 4.8, CLR 4.0.30319.42000). Новых пользовательских модулей нет: выпуск увеличивает PATCH.

## Измеренный результат

Медианы времени в миллисекундах; меньше — быстрее. Для каждого сценария выполнен прогрев и 5 либо 7 повторов (точное число, p95 и сборки GC сохранены в JSON).

| Операция | 6.4.0, мс | 6.4.1, мс | Отношение времени |
|---|---:|---:|---:|
| Модель типа 0 | 212.35 | 98.34 | 2.16× |
| Модель типа 3 | 138.71 | 59.72 | 2.32× |
| Модель типа 4 (ПТК) | 89.47 | 42.22 | 2.12× |
| Модель типа 7 | 284.25 | 93.12 | 3.05× |
| 50 сфер подшипников | 88.63 | 24.03 | 3.69× |
| 50 тел вращения | 3.39 | 1.74 | 1.95× |
| Изменение скорости при открытом редакторе | 28.80 | 3.09 | 9.31× |
| Повторное оформление окна | 26.03 | 15.35 | 1.70× |

Идентификаторы типов соответствуют `Engine.Starter` в исходном коде. При построении сохранены размеры, сегментация, треугольники, аналитические тела и детализация подшипников. Оптимизация сфер и тел вращения влияет на опоры всех типов передач.

Видимая неподвижная WebGL-сцена (один куб, 12 треугольников) за интервал 750 мс: **79 кадров → 0 кадров**. Новая поза после простоя вызывает кадр, выбор детали продолжает работать. Это измерение числа отрисовок, а не процент экономии CPU/GPU. Движение камеры с затуханием, объединение сообщений, скрытие/возврат страницы и повторное изменение во время кадра проверены отдельно планировщиком.

Изменения скорости, привязки, чувствительности камеры и автосохранения больше не оформляют заново все окна и не перестраивают сетку WPF. При изменении языка, темы или цветов интерфейс обновляется; качество перестраивает предпросмотр. Сохранение настроек и резервной копии остаётся синхронным. Число событий Invalidated в сценарии повторного оформления окна плюс изменения скорости: **5663 → 1266**.

Повторяющиеся строки состояния и ASCII больше не проходят каждый раз через большой регулярный шаблон перевода. Тест 10 000 ASCII-строк: 12657.724 → 0.684 мс. Тест 2000 строк состояния из 100 вариантов: 1803.342 → 0.452 мс. Это прогретые микротесты; они не означают такое же ускорение приложения целиком. Кэш ограничен; длинные строки не накапливаются.

## Что изменено

- Общие таблицы синусов/косинусов для шариков и дорожек; вершины сферы вычисляются один раз и переиспользуются при создании треугольников.
- Настройки клонируются без промежуточного JSON. Все сохраняемые поля и независимость словаря цветов проверены.
- Оформление WinForms, нативные темы и измерение панели параметров выполняют меньше повторной работы. Парсинг цветов кэшируется.
- Регулярный шаблон перевода создаётся по необходимости; повторный перевод кэшируется с ограничением размера.
- WebGL рисует по изменению сцены, камеры и взаимодействию; пакет обновлений объединяется в кадр. Анимационные сообщения поз продолжают вызывать отрисовку.

## Проверки и границы результата

Все 7016 прежних утверждений и 41 новое прошли (7057 суммарно). Проверены 13 типов передач, изменения параметров, рабочие пространства, настройки RU/EN, отделяемая панель, ступени, робот, экспорт и сообщения об ошибках. Дополнительно прошли `tools/ci_verify.ps1`: кэши проектов, быстрый ПТК, нативное CAD-ядро, движение/габариты, сечения/эскизы, редактирование STEP, старый волновой экспорт и 22 проверки контроллера Three.js. Новый JS-планировщик проверяет покой, затухание камеры, видимость и пакетирование.

Для четырёх радиусов сферы и профиля дорожки SHA256 последовательностей точек, нормалей и индексов строго совпал с 6.4.0. У самого малого радиуса сохранено прежнее отсечение вырожденных треугольников.

Формулы решателя не изменялись. Время 60 обновлений поз ПТК: 5.286 → 5.651 мс: улучшение не подтверждено. Первый запуск окна измерен по одному разу (5003 → 4500 мс), поэтому ускорение холодного запуска не заявляется. Пиковый working set тестового процесса: 518.3 → 576.2 МиБ; уменьшение памяти не заявляется. Эти разовые пики включают последовательное создание моделей и работу GC, отдельного долговременного теста памяти нет.

## Воспроизведение

`powershell -NoProfile -File src/build.ps1 -OutputFolder Windows`

`Windows/GearLab.exe --optimization641-test results/optimization`

`Windows/GearLab.exe --performance-test results/performance`

`Windows/GearLab.exe --performance-web-test results/web`

`node tools/test_render_scheduler.mjs`

Для WebView2 нужен установленный Microsoft Edge WebView2 Runtime. Каждая тестовая команда использует отдельный профиль. Сравнение выполнялось инструментированными сборками: базовый код 6.4.0 (commit f6cb7f4f097547be0f838aa3564ca7eeb499d2af) и тот же измерительный код; в JS добавлен только счётчик кадров. Web-сравнение использовало одинаковый C#-хост и разные версии JS. Публикуемый EXE собирается CI из исходников; время на другом оборудовании будет отличаться.
