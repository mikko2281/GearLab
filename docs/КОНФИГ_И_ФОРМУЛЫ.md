# GearLab 5.5 — конфиг, устройство и формулы

Основной структурированный файл: [GearLab.config.json](GearLab.config.json). Эта памятка создана из него.

## Что можно менять

- Этот файл описывает реализацию 5.5. Программа не загружает из него формулы и коэффициенты. Правка этого файла сама по себе не меняет расчёты.
- Настройки интерфейса меняются в разделе Настройки и сохраняются в %LOCALAPPDATA%/GearLab/settings.json. Пример settings.example.json лежит рядом; существующие настройки пользователя не заменены.
- Размеры, нагрузки и моторы меняются в свойствах проекта; сохраняйте свой проект через интерфейс. Изменение геометрии требует перестроения корпуса перед экспортом.
- Для изменения алгоритма редактируют указанные исходники и пересобирают программу. Поле source относится к каталогу исходного выпуска, а не к установленным системным библиотекам.
- Формулы ниже — математическая запись, а не готовые выражения для вставки в CAD. В них знак ^ означает степень; CAD использует **. Не выполнять строки формул как произвольный код.

## Единицы

| Величина | Единицы |
|---|---|
| length | мм в CAD и каркасе; плечо для Н·м переводится в метры делением на 1000 |
| volume | мм³; 1 мм³ = 1e-9 м³ |
| mass | кг |
| force | Н |
| torque | Н·м в расчёте моторов; Н·мм в подборе сечения корпуса |
| stress | МПа = Н/мм² |
| density | кг/м³ |
| speed | об/мин для моторов; °/с для вращательного шарнира, мм/с для линейного |
| angles | параметры интерфейса — градусы; sin/cos/tan в математических формулах — радианы, если явно не сказано иначе |
| efficiency | безразмерный коэффициент 0 < eta <= 1; 0.7 означает 70% |

## Внутреннее ядро B-rep (самостоятельный редактор удалён)

1. Проект содержит параметры, эскизы и упорядоченную историю операций.
2. Формулы вычисляются с проверкой имён, конечности чисел и циклических зависимостей.
3. Операции строят точные B-rep тела в Open CASCADE: примитивы, выдавливание, вращение, лофт, протяжка, булевы операции и модификаторы.
4. Проверяются валидность твёрдого тела и ненулевой объём; отдельно создаётся треугольный предпросмотр.
5. STEP хранит CAD-поверхности; STL хранит треугольники и не переносит историю операций.

```json
    "/",
    "**",
    "скобки"

  "expression_functions": [

  "trigonometry_in_cad": "sin/cos/tan в редакторе выражений принимают градусы.",

  "sketch_max_iterations": 50
```

**Реализованные формулы:**

### Привязка перемещения (`ui.snap`)

```text
x_snap = Round(x / h) * h
```

x — координата, мм; h — SnapStep, мм; Round — System.Math.Round; середины округляются к ближайшему чётному.

Применяется при SnapEnabled=true; при false координата не округляется.

Код: `src/AppSettings.cs`.

### Объём, масса и центр масс (`cad.volume_mass`)

```text
V = integral_V dV
m = rho * V_mm3 * 1e-9
c = integral_V r dV / V
```

rho — плотность, кг/м³; V_mm3 — объём тела в мм³; c — локальный центр масс.

Native STEP использует объём и центр масс OCCT. Для мотора применяется явно заданная MassOverride; служебные направляющие имеют нулевую массу.

Код: `kernel/cad_kernel.py`, `src/RobotCad.cs`.

### Численное решение ограничений эскиза (`cad.constraint_solver`)

```text
J_ij ~= (r_i(x+h_j*e_j) - r_i(x)) / h_j
h_j = 1e-5 * max(1, abs(x_j))
(transpose(J)*J + lambda*I) * dx = -transpose(J)*r
x_next = x + dx
DOF = number_of_variables - rank(J)
```

r — вектор невязок ограничений; J — численный якобиан; lambda — демпфирование, начально 1e-5; DOF — оценка оставшихся степеней свободы.

До 50 итераций. Ранний выход при max|r|<1e-6; невязка >1e-4 вызывает ошибку. Невязки разных связей нормированы по-разному, в том числе угол, поэтому число не является единым производственным допуском. Начиная с 5.3 вырожденное направление отрезка отклоняется до вычисления направленных невязок.

Код: `kernel/sketch_solver.py`.

### Примеры невязок ограничений (`cad.constraint_residuals`)

```text
horizontal: u_y = 0
vertical: u_x = 0
coincident: p_a - p_b = 0
length: norm(u) - L = 0
parallel: cross2(u,v) / max(norm(u),norm(v)) = 0
perpendicular: dot(u,v) / max(norm(u),norm(v)) = 0
directional_constraints: hypot(u_x,u_y)>=1e-7 мм для каждого участвующего отрезка
```

u,v — векторы отрезков, мм; cross2(u,v) — u_x*v_y-u_y*v_x; L — заданный размер, мм.

Перед horizontal, vertical, parallel, perpendicular, angle и tangent длина каждого участвующего отрезка проверяется явно. Нулевая длина одного или обоих отрезков вызывает ошибку неопределённого направления. Дополнительный численный предохранитель length(v)=max(1e-10,hypot(v)) сохраняется; он сам по себе не заменяет эту проверку.

Код: `kernel/sketch_solver.py`.

**Ограничения:**

- Точные поверхности не означают наличие заводской истории у импортированного STEP.
- После сильного изменения топологии иногда требуется повторный выбор граней и рёбер.
- Не все операции Fusion реализованы; CAM, PCB и полноценный FEA отсутствуют.

Исходники модуля: `src/CADModel.cs`, `src/CADExpression.cs`, `src/CADKernel.cs`, `kernel/cad_kernel.py`, `kernel/sketch_solver.py`.

## Свободный механизм: валы, шестерни, шкивы

1. Добавить входной вал, назначить момент и обороты.
2. Посадить шестерни/шкивы на валы и создать связи gear, belt или coupling.
3. Проверить геометрию зацепления; обойти граф от входа и распространить скорости и КПД.
4. Просуммировать нагрузки от выходов к входу; сравнить требуемый момент с заданным.

**Параметры и область действия:**

```json
{
  "new_project_defaults": {
    "InputRpm": 300,
    "InputTorque": 2
  },
  "new_link_default_efficiency": 0.97,
  "input_rpm_abs_max": 60000,
  "input_torque_range_Nm": [
    0,
    1000000
  ],
  "axes": "Параллельные оси Z.",
  "gear_constraints": "Одинаковые Module и PressureAngle; противоположные HelixAngle; одинаковая принадлежность к herringbone.",
  "centre_distance_tolerance_mm": 0.02,
  "minimum_axial_overlap_mm": 0.1
}
```

**Реализованные формулы:**

### Скорость и механическая мощность (`transmission.power`)

```text
omega = 2*pi*n/60 = pi*n/30
P = abs(omega) * T
```

n — об/мин; omega — рад/с; T — неотрицательная величина момента, Н·м; P — Вт.

Код: `src/MechanismSolver.cs`, `src/WaveReducer.cs`.

### Передача скорости по связи (`mechanism.speed`)

```text
gear: k = n_driven/n_driver = -z_driver/z_driven
belt: k = D_driver/D_driven
coupling: k = 1
s_out = s_parent*k
n_out = n_input*s_out
```

s — отношение скорости данного вала к входному; D — делительный диаметр, мм; z — число зубьев.

Знак минус означает обратное вращение внешней зубчатой пары. Открытый ремень сохраняет направление.

Код: `src/MechanismSolver.cs`.

### КПД, доступный момент и приведение нагрузки (`mechanism.torque`)

```text
eta_path = product(eta_link)
T_available = T_input*eta_path/abs(s)
T_parent_required += T_child_required*abs(s_child/s_parent)/eta_link
overloaded = T_root_required > T_input + 1e-8
```

eta — КПД связи, 0<eta<=1; s — отношение скорости к входному валу; T — Н·м.

Требуемый момент каждого вала начинается с его LoadTorque. Приведение выполняется от листьев дерева к входу.

Код: `src/MechanismSolver.cs`.

### Усилия в зацеплении (`mechanism.forces`)

```text
Ft = 2000*T_driver/d_driver_mm
Fr = Ft*tan(alpha)
Fa = Ft*abs(tan(beta))
```

Ft — окружная сила, Н; Fr — радиальная сила для gear, Н; Fa — осевая сила для косозубого gear, Н; T_driver — момент, необходимый для данной ветви, Н·м; alpha — PressureAngle в радианах; beta — HelixAngle в радианах.

Для herringbone Fa принимается равной нулю; для ремня Fr и Fa равны нулю в этой модели. Это упрощение, не расчёт реакций опор.

Код: `src/MechanismSolver.cs`.

**Ограничения:**

- Расчёт допускает разветвлённое дерево без замкнутых контуров и нескольких путей передачи момента.
- AvailableTorque на каждой ветви предполагает весь входной момент для этой ветви. Эти предельные моменты нельзя одновременно получить на всех выходах.
- КПД задаётся пользователем; нет динамики, деформаций и проверки прочности зубьев.
- Ремень считается без проскальзывания; Ft — разность натяжений, а не полная нагрузка на опоры.
- Внутренние венцы и рейки доступны как CAD-геометрия; отдельный решатель их зацепления в графе не реализован.

Исходники модуля: `src/MechanismModel.cs`, `src/MechanismSolver.cs`, `src/MechanismCad.cs`.

## Редукторы: циклоидальный, зубчатая пара, ремень, планетарный

1. Выбрать тип во вкладке Редукторы.
2. Проверить диапазоны размеров и подобрать целые числа зубьев.
3. Рассчитать профиль, габариты и геометрические ограничения; построить сборку и движение.
4. Экспортировать выбранные детали; перечень шаблонных покупных компонентов требует проверки по каталогу.

**Параметры и область действия:**

```json
{
  "general_ratio_range": [
    1,
    200
  ],
  "cycloid_ratio": "Целое 2–120 для неподвижного кольца; 3–120 для вращающегося кольца.",
  "cycloid_discs": [
    1,
    2
  ],
  "cycloid_output_pins": [
    3,
    16
  ],
  "planet_stages": "0 = автоматический подбор 1–3, либо явно 1–3.",
  "planet_ratio_tolerance_percent": [
    0,
    10
  ],
  "default_pressure_angle_deg": 20
}
```

**Реализованные формулы:**

### Подбор зубьев ведомого колеса (`reducers.pair_rounding`)

```text
z2 = RoundAwayFromZero(i_requested*z1)
i_actual = z2/z1
error_percent = 100*(i_actual/i_requested-1)
```

i_requested — запрошенное передаточное число; z1,z2 — целые числа зубьев.

Код: `src/GearCalculator.cs`.

### Длина открытого ремня (`belt.geometry`)

```text
d1 = pitch*z1/pi
d2 = pitch*z2/pi
delta = (d2-d1)/2
beta = asin(delta/C)
L = 2*sqrt(C^2-delta^2)+pi*(d1+d2)/2+2*delta*beta
belt_teeth_candidate = Round(L/pitch)
```

pitch — шаг ремня, мм; C — межосевое расстояние, мм; L — длина по делительной линии, мм.

Требуется C>(d1+d2)/2 и C>|delta|. Округление зубьев не подстраивает автоматически C под каталог.

Код: `src/GearCalculator.cs`.

### Планетарная ступень с закреплённым кольцом (`planet.geometry`)

```text
zr = zs+2*zp
i = 1+zr/zs
(zs+zr) mod planets = 0
(zs+zp)*sin(pi/planets) > zp+2
i_total = product(i_stage)
```

zs — зубья солнца, вход; zr — зубья неподвижного кольца; zp — зубья сателлита; planets — число сателлитов; выход — водило.

Последнее неравенство проверяет непересечение соседних сателлитов по вершинам при стандартной высоте зуба. Подбор минимизирует число ступеней в допуске, затем отклонение; при равенстве выбирает меньший максимум zr.

Код: `src/GearCalculator.cs`, `src/PlanetaryTrain.cs`.

### Циклоидальная схема и посадки (`cycloid.counts`)

```text
fixed_ring: N=i+1; lobes=N-1; n_out=-n_in/i
rotating_ring: N=i; lobes=N-1; n_out=+n_in/i
roller_spacing = 2*R*sin(pi/N)
output_hole_diameter = output_pin_diameter+2*e+2*c
outer_envelope = 2*(R+roller_diameter/2)
k = e*N/R < 1
```

N — число пальцев/роликов кольца; R — радиус их центров, мм; e — эксцентриситет, мм; c — радиальный зазор, мм.

Для вращающегося кольца диск не вращается относительно рамы, но его центр совершает орбитальное движение.

Код: `src/GearCalculator.cs`.

### Профиль циклоидального диска (`cycloid.profile`)

```text
rr = roller_diameter/2+c
psi = atan2(sin((1-N)*t), R/(e*N)-cos((1-N)*t))
x(t) = R*cos(t)-rr*cos(t+psi)-e*cos(N*t)
y(t) = -R*sin(t)+rr*sin(t+psi)+e*sin(N*t)
```

t — параметр от 0 до 2*pi, рад; x,y — мм; rr — эффективный радиус ролика с зазором.

Дискретизация: steps=ceil(max(Segments,N*40)/(N-1))*(N-1). Проверяются перемычки по минимальному радиусу профиля.

Код: `src/GearCalculator.cs`.

### Проверка локального подрезания смещённого профиля (`cycloid.undercut`)

```text
curvature = (x_prime*y_second-y_prime*x_second)/(x_prime^2+y_prime^2)^(3/2)
offset_speed_factor = 1+rr*curvature
min(offset_speed_factor) > 0
```

x,y — исходная кривая центров: x=R*cos(t)-e*cos(N*t), y=-R*sin(t)+e*sin(N*t); rr — радиус ролика с зазором.

Минимум ищется выборкой max(1440,N*50) точек; это реализованная локальная численная проверка, не полный контактный анализ.

Код: `src/GearCalculator.cs`.

**Ограничения:**

- Геометрический подбор не подтверждает подрезание всех зубьев, контактную прочность, ресурс и реальные нагрузки подшипников.
- Два циклоидальных диска относятся к одной ступени; передаточное отношение не перемножается.
- Ближайшая целая длина ремня — кандидат: нужны каталог, натяжитель или новое межосевое расстояние.

Исходники модуля: `src/GearCalculator.cs`, `src/PlanetaryTrain.cs`, `src/CadBuilder.cs`, `src/SceneMotion.cs`.

## Библиотека зубчатых CAD-деталей

1. Выбрать пресет прямозубой, косозубой, шевронной шестерни, внутреннего венца или рейки.
2. Построить эвольвентные боковые поверхности и тело; для косого зуба создать сечения с поворотом по высоте.
3. Вставить тело в CAD/механизм; геометрия и расчёт передачи являются отдельными этапами.

**Параметры и область действия:**

```json
  ],
  "module_mm": [

    10
  ],
  "thickness_mm": [
    0.5,
    200
  ],
  "pressure_angle_deg": [
    14,

  ],
  "helical_angle_abs_deg": [
    1,
    40

  "module_convention": "В этой реализации d = m*z, в том числе для косого зуба. Не подменять m нормальным модулем без преобразования.",
  "profile_approximation": "Боковая эвольвента интерполируется по 13 радиусам; ниже базовой окружности используется прямой переход. Это не точная трохоида инструмента."
```

**Реализованные формулы:**

### Размеры внешней шестерни и пары (`gears.dimensions`)

```text
d = m*z
r_pitch = d/2
r_base = r_pitch*cos(alpha)
r_tip = r_pitch+m
r_root = r_pitch-1.25*m
a = m*(z1+z2)/2
i_abs = z2/z1
```

m — модуль данной реализации, мм; z — число зубьев; alpha — угол зацепления, рад; a — межосевое расстояние, мм.

Код: `kernel/cad_kernel.py`, `src/GearCalculator.cs`, `src/MechanismModel.cs`.

### Эвольвента и толщина зуба (`gears.involute`)

```text
t = sqrt(max(0,(r/r_base)^2-1))
inv(r) = t-atan(t)
half = pi/(2*z)-backlash/(2*r_pitch)
offset = half+inv(r_pitch)
external_flank_angle(r) = offset-inv(r)
internal_cutout_angle(r) = pi/z-(offset-inv(r))
```

r — радиус точки, мм; backlash — линейный боковой зазор, мм; half — половина угловой толщины зуба на делительной окружности, рад.

Для контура выреза внутреннего венца: r_root=r_pitch-m, r_tip=r_pitch+1.25*m. Отрицательная толщина зуба запрещена.

Код: `kernel/cad_kernel.py`.

### Косой зуб, шеврон и рейка (`gears.helix_rack`)

```text
twist = thickness*tan(beta)/r_pitch
helical: rotation(z_height)=twist*z_height/thickness
herringbone: rotation идёт 0 -> twist/2 -> 0
rack_pitch = pi*m
```

twist — полный угол закручивания, рад; thickness — ширина венца, мм; beta — угол наклона, рад; rack_pitch — линейный шаг рейки, мм.

### Прямая кинематика (`robot.kinematics`)

```text
B_j = Translate(offset_j)*End_parent
Output_j = Motion(axis_j,q_j)*B_j
End_j = Translate(end_vector_j)*Output_j
p_world = Transform(p_local, pose_matrix)
```

B_j — базовая система шарнира; Motion — поворот на q в градусах либо сдвиг на q мм; единичная матрица для неподвижного; End_parent — конечная система родителя; единичная для корня.

Порядок записан как в WPF Matrix3D с векторами-строками. Для библиотек с векторами-столбцами порядок нужно транспонировать, а не копировать буквально.

Код: `src/RobotModel.cs`, `src/RobotCad.cs`.

### Демонстрационная анимация шарнира (`robot.animation`)

```text
A=(q_max-q_min)/2
q_c=(q_max+q_min)/2
start=asin(clamp((q_initial-q_c)/A,-1,1))
q(t)=q_c+A*sin(start+t*Speed/A)
q_final=clamp(q(t),q_min,q_max)
```

t — фаза времени анимации после множителя скорости показа; q — ° для вращения, мм для линейного перемещения; Speed — °/с или мм/с.

При A≈0 сохраняется положение. Производная по времени ограничивается Speed, однако ускорения и требуемая для них инерционная нагрузка не рассчитываются.

Код: `src/RobotModel.cs`.

### Силы тяжести и внешняя нагрузка (`robot.gravity`)

```text
F_part=(0,0,-m*g)
F_tool=(ForceX,ForceY,ForceZ-Payload*g)
r_m=(load_point_world-origin_joint)/1000
```

m,Payload — кг; g — Gravity, м/с²; r_m — плечо, м; ForceX/Y/Z — внешняя сила в мировой системе, Н.

Вес детали приложен в её мировом центре масс. Полезная нагрузка и внешняя сила звена приложены в Tip, а у последнего звена с включённым референсным захватом — в точке TCP на конце пальцев. Это добавление выполнено вместе с геометрией захвата, чтобы масса груза не осталась ошибочно на запястье.

Код: `src/RobotSolver.cs`, `src/ReferenceRobotDesign.cs`.

### Момент или усилие шарнира (`robot.effort`)

```text
rotational: tau_signed = sum(dot(cross(r_m,F),axis_unit))
linear: force_signed = sum(dot(F,axis_unit))
required = abs(signed_effort)*SafetyFactor
```

axis_unit — единичный вектор оси в мировой системе; required — Н·м для вращения или Н для линейного шарнира.

Суммируются учтённые детали с OwnerId среди потомков и их нагрузки. Направляющие скелета исключены; неподвижному соединению моторный критерий не предъявляется.

Код: `src/RobotSolver.cs`.

### Вращательный мотор и редуктор (`robot.motor`)

```text
T_available=MotorTorque*Reduction*Efficiency
T_motor_required=T_required/(Reduction*Efficiency)
n_motor=Speed_deg_s/6*Reduction
Margin=T_available-T_required
Enough=(T_required<=T_available+1e-9) AND (n_motor<=MotorMaxRpm+1e-7)
```

Reduction — положительное отношение скорости мотора к выходу; Efficiency — КПД; Margin — разность в Н·м, не коэффициент запаса.

Для CustomTransmission: Reduction=1/abs(output.SpeedRatio), Efficiency=output.PathEfficiency.

Код: `src/RobotSolver.cs`.

### Линейный привод через винт (`robot.screw`)

```text
F_available=MotorTorque*Reduction*Efficiency*2*pi/(ScrewLead/1000)
T_motor_required=F_required*(ScrewLead/1000)/(2*pi*Reduction*Efficiency)
n_motor=Speed_mm_s/ScrewLead*60*Reduction
```

ScrewLead — ход винта за оборот, мм/об; F — Н; T — Н·м.

Потери объединены в заданном Efficiency. Отдельного расчёта трения, самоторможения и критической скорости винта нет.

Код: `src/RobotSolver.cs`.

**Ограничения:**

- Статика: нет инерционных моментов разгона/торможения, упругости, усталости, нагрева и расчёта крепежа.
- Если требуемые обороты выше MotorMaxRpm, результат не подтверждается. Ниже этого предела момент всё равно должен быть введён по реальной характеристике.
- Синусоидальная анимация показывает связи и пределы; она не является динамической симуляцией или контроллером реального робота.
- Максимум, найденный в выборочных позах, не является доказанным глобальным максимумом.

Исходники модуля: `src/RobotModel.cs`, `src/RobotCad.cs`, `src/RobotSolver.cs`, `src/RobotJointControllers.cs`, `src/ReferenceRobotDesign.cs`.

**Реализованные формулы:**

### Консервативная нагрузка для генератора (`body.load_envelope`)

```text
b_root=0
b_child=b_parent+norm(End_parent)+travel_parent+norm(Offset_child)
travel_j=max(abs(Minimum_j),abs(Maximum_j)) для линейного шарнира; иначе 0
R_part=b_joint+norm(LocalTransform(COM_part))+(InputSide ? 0 : travel_joint)
R_tool=b_joint+travel_joint+norm(End_joint)+ToolLoadExtension
F_bound=SafetyFactor*sum(mass_part*g+Payload*g+norm(ExternalForce)+reserve_mass*g)
M_bound_Nmm=SafetyFactor*sum(force_magnitude_N*point_radius_mm)
DesignMomentNmm=max(current_rotational_required_Nm*1000,M_bound_Nmm)
DesignTorqueNmm=max(M_bound_Nmm,current_rotational_required_Nm*1000,MotorTorque*Reduction*Efficiency*1000)
AxialForceN=F_bound
```

b_joint — верхняя граница пути от оси подбираемого шарнира до начала данного звена, мм; R_part,R_tool — оценки радиуса положения центра масс/точки силы, мм; Offset_child — полный вектор монтажного смещения дочернего шарнира, мм; COM_part — локальный центр масс фактической детали; reserve_mass — оценка массы корпуса, если он включён, но ещё не построен; ToolLoadExtension — для включённого захвата последнего звена: толщина инструментального фланца + 64 мм до конца пальцев; иначе 0.

Корневое смещение самого подбираемого шарнира перемещает ось вместе с нагрузкой и не является плечом. Смещения дочерних суставов учитываются по каждому пути, а не суммой длин всех ветвей. Для известных внутренних вращений/орбит применяется радиальная граница ComponentRadius; неподдержанное вложенное движение отклоняется. current_required допускается только в Н·м: линейный корневой шарнир блокируется до расчёта. При current_required=0 оценка M_bound сохраняется. Оценка будущей массы остаётся приближённой.

Код: `src/BodyLoadEnvelope.cs`, `src/ProceduralBodyModel.cs`.

### Оценка массы ещё не построенного корпуса (`body.mass_envelope`)

```text
m_part=MassOverride, если задана; иначе Volume_mm3*Density*1e-9
V_est=pi*((GearboxDiameter/2+6)^2-(GearboxDiameter/2)^2)*(MotorLength+GearboxLength)+pi*(400-256)*Length
reserve_mass=max(0.25,V_est*Density*1e-9+0.18)
reserve_radius=b_joint+travel_joint+max(Length,MotorLength+GearboxLength+GearboxDiameter+norm(MotorOffsetXY))
MassKg=sum(учтённые фактические массы+Payload+резервы отсутствующих корпусов)
```

V_est — приближённый объём, мм³; Density — плотность звена, кг/м³.

Резерв добавляется только при BodyGenerator.Enabled=true и GeneratedBody=null. При наличии готового корпуса учитываются массы и центры его отдельных деталей. Масса резерва является допущением, а не подтверждённой массой будущего тела.

Код: `src/BodyLoadEnvelope.cs`, `src/RobotCad.cs`.

### Совместный подбор круглой трубы Connected=true (`body.connected_section`)

```text
fw=max(wall,FrameWall)*Style.Strength
r0=max(18,fw+CableDiameter+4)*(1+0.12*(1-Style.Slimness))
r_inner=r-fw
A=pi*(r^2-r_inner^2)
I=pi*(r^4-r_inner^4)/4
J=2*I
sigma=abs(DesignMomentNmm)*r/I+abs(AxialForceN)/A
tau=abs(DesignTorqueNmm)*r/J
sigma_equivalent=sqrt(sigma^2+3*tau^2)
r=max(r0,fw+0.5); увеличивать r на 0.5 мм до sigma_equivalent<=AllowableStressMPa
если допустимый радиус не найден до 70 мм — ошибка, геометрия не принимается
```

wall — max(2.4,MinWall), мм; fw — стенка каркаса, мм; r — наружный расчётный радиус, мм; A — площадь поперечного сечения, мм²; I — момент инерции круглого сечения, мм⁴; J — полярный момент инерции круглой трубы, мм⁴; sigma,tau,sigma_equivalent — напряжения, МПа.

В 5.3 учтены изгиб, осевая сила и кручение. Для круглой трубы применяется упругая формула tau=T*r/J вместо тонкостенной аппроксимации Бредта старой ветки. Для rounded_rectangle круглая оценка остаётся приближённой. FEA стыков, вставок и печатной анизотропии отсутствует. Для ReferenceDesign=true этот расчёт используется как исходный размер, а не как решение напряжений произвольной кассеты; прочность остаётся pending.

Код: `kernel/body_section.py`, `kernel/connected_body.py`.

### Габариты корпуса привода и крепёжного круга (`body.envelope`)

gap — Clearance, мм; boss — радиус прилива под вставку, мм; r_bolt_circle — радиус, не диаметр; BodyMate.BoltCircle хранит удвоенное значение.

Радиусы учитывают квадратный габарит мотора и смещение его центра; фактический разъём требует отдельной проверки.

Код: `kernel/connected_body.py`.

### Осевой переход трубы (`body.route`)

```text
r_bound=r для oval
r_bound=r*(sqrt(2)*(1-roundness)+roundness) для rounded_rectangle
bend_radius=1.55*r_outer_bound
trim=bend_radius*tan(turn_angle/2)
route_score=sum(straight_lengths)-2*sum(trim)+sum(bend_radius*turn_angle)
```

r_outer_bound — габарит профиля с зазором и оболочкой; turn_angle — изменение направления, рад; roundness — значение стиля, при расчёте габарита ограничено 0.1–0.95.

Проверяются оба осевых направления входа и конечный набор длин. Для простого углового перехода радиус может быть уменьшен с ограничением места >1.3*r_outer_bound+4. Кандидаты сортируются по длине. Это поиск среди шаблонов, не глобальная оптимизация всей конструкции.

Код: `kernel/joint_geometry.py`, `kernel/connected_body.py`.

### Скруглённое седло вместо треугольной перемычки (`body.saddle`)

```text
n_x=(R_big-R_small)/distance
n_y=sqrt(1-n_x^2)
A=(R_big*n_x,R_big*n_y)
B=(distance+R_small*n_x,R_small*n_y)
```

distance — расстояние между центрами окружностей, мм; R_big,R_small — радиусы двух сопрягаемых окружностей, мм.

Прямые общие касательные и дуги образуют точную выпуклую оболочку двух окружностей; контур выдавливается на заданную глубину. Требуется |n_x|<1.

Код: `kernel/joint_geometry.py`.

### Отверстия и некоторые фиксированные посадки Connected (`body.bolts_fits`)

```text
angle_k=pi/4+2*pi*k/count
bolt_point_k=origin+pc*cos(angle_k)*local_x+pc*sin(angle_k)*local_y
clearance_hole_diameter=bolt+0.4
pilot_hole_diameter=MotorPilot+2*gap
bearing_seat_radius=BearingOuter/2+0.075
output_journal_radius=BearingInner/2-0.02
```

pc — радиус крепёжного круга, мм; count — обычно 4; bolt — номинальный диаметр винта, мм.

0.075 и 0.02 мм — радиальные добавки. Посадочный диаметр подшипника увеличивается на 0.15 мм, шейка уменьшается на 0.04 мм. Это зафиксированные допущения, не стандартная посадка H7 и не значение ShaftFit.

Код: `kernel/connected_body.py`.

### Выбор длины общего винта (`body.screw_length`)

```text
stack+3 <= L <= stack+engagement-0.4
L = первый допустимый из [6,8,10,12,14,16,18,20,25,30,35,40]
```

stack — толщина пакета, мм; engagement — доступная глубина зацепления, мм; L — длина винта, мм.

Если допустимой длины нет, построение выдаёт ошибку. Этот подбор не проверяет срыв резьбы, натяг, затяжку или доступ инструмента.

Код: `kernel/connected_body.py`.

**Ограничения:**

- Для прежнего трубчатого режима используется совместная номинальная оценка круглой трубы. В режиме ReferenceDesign она задаёт только исходный размер; напряжения коробчатого корпуса, вырезов, стыков, крепежа и печатных слоёв отдельно не решаются.
- Генератор Connected не создаёт развилку с несколькими дочерними звеньями и не поддерживает процедурное крепление линейного привода.
- Гибкие провода, реальные разъёмы и внутренняя передача требуют отдельного проектирования. Зарезервированный объём не означает готовую разводку.
- Старая ветка Connected=false использует другую оценку сечения; её формулы нельзя приписывать новой ветке.
- Константы вроде радиального зазора подшипника 0.075 мм являются геометрическими допущениями, не выбранным стандартным полем допуска.
- Результат всегда ReadyForManufacture=false; изменять этот флаг не заменяет инженерную проверку.
- Геометрическая оценка плеча является верхней границей для учтённых масс текущей модели и заданных точечных сил. Масса ещё не построенного корпуса оценивается приближённо: это не доказанная верхняя граница его окончательной массы и не глобальный оптимизатор конструкции.

Исходники модуля: `src/ProceduralBodyModel.cs`, `src/RobotProceduralWorkspace.cs`, `src/RobotConnections.cs`, `kernel/connected_body.py`, `kernel/joint_geometry.py`, `kernel/procedural_body.py`, `src/BodyLoadEnvelope.cs`, `kernel/body_section.py`, `kernel/reference_enclosure.py`, `src/ReferenceRobotDesign.cs`, `src/ProceduralBodyForm.cs`.


## РОБОТ1.blend · размерный Г-образный корпус

1. Исходная форма автора используется как размерный референс; треугольники не превращаются в STEP-грани.
2. Масштаб задаётся по полной высоте исходной геометрии: 800 мм.
3. Используются шесть реальных стыков с осями +Z, −Y, +Y, −Y, +Z, +Y; смещения костей сохраняются пространственно.
4. Г-образное звено состоит из точного четверть-тора и цилиндра. Перпендикулярные узлы объединяют цилиндрическую ногу и округлый переход.
5. Корпус охватывает следующий неподвижный статор и соединяется с его реальным задним монтажным фланцем.
6. Моторные объёмы вырезаются из каркаса. Доступность вставок проверяется булевыми пересечениями; оболочка и крышка имеют собственный крепёж.
7. На коротком запястье задние винты переносятся на доступную боковую сторону.
8. Экспорт каждой детали проверяется повторным чтением STEP и сравнением объёма; внешний вид сверяется с исходным файлом.

**Реализованные формулы:**

### Масштаб и размещение осей автора (`author.scale`)

```text
s=800/(2.1876449585-(-2.1889286041))=182.791398 мм/ед.
P_i=s*(P_source_i-[0,0.2247911543,-2.1889286041])
P_1.z += 10; End_1.z -= 10 (высоты P_2…P_6 не меняются)
End_4.y -= 16.6 (дополнительное место для перпендикулярного NEMA 17)
D_tube=0.425682962*s=77.8111837 мм
Axis=AxisReversed ? -Axis_mode : Axis_mode
```

s — мм на единицу Blender; P_source_i — центры измеренных швов, исходные координаты; P_i — координаты осей, мм; AxisReversed — обращает как вращение, так и ориентацию монтажной модели привода.

Точные измеренные координаты и SHA-256 исходного файла записаны в examples/reference/Robot1.measurements.json. Размерный исходник не является расчётом пригодности к печати.

Код: `src/RobotModel.cs`.

### Круглое колено и силовая втулка следующего привода (`author.elbow`)

```text
r=max(r_section,D_tube/2-skin-gap,r_root_flange-frame_wall)
R_bend=max(r+skin+gap+0.5,CableBendRadius)
L=norm((B-A)-n_root*dot(B-A,n_root))
L > R_bend+2*frame_wall
колено: четверть-тора с большим радиусом R_bend и малым радиусом r
прямой участок: цилиндр радиуса r, длина L-R_bend
r_child_sleeve = r_child_case + gap + frame_wall
каркас=Cut(наружный силовой объём,внутренний объём и защищённые приводы)
оболочка: отступы gap и gap+skin; бобышки ограничены наружным силовым контуром
```

A — центр выходного фланца; B — ось следующего привода; n_root — ось выходного фланца; r_section — радиус, выбранный по совместной изгибной, крутильной и осевой номинальной оценке.

Формула круглого сечения задаёт нижнюю границу размера. Она не подтверждает прочность всех локальных вырезов, колен и стыков. Корректность B-rep и отсутствие пересечений не заменяют расчёт прочности.

Код: `kernel/blender_enclosure.py`, `kernel/reference_enclosure.py`, `kernel/connected_body.py`.

### Место для полного вала мотора и опоры основания (`author.shaft_clearance`)

```text
shaft_top = -GearboxLength - Plate + MotorShaftLength
shaft_top + gap <= -BearingWidth
ground_space = GroundDepth + rear_stator_plane
ground_space >= mount_plate + floor_plate
```

shaft_top — конец монтажного габарита вала мотора, локальная координата мм; rear_stator_plane — отрицательная координата нижней крышки; ground_space — свободное место под крышкой до стола.

При недостатке места построение останавливается с указанием причины. Длина исходного вала мотора не укорачивается ради прохождения проверки.

Код: `kernel/connected_body.py`, `src/ProceduralBodyModel.cs`.

**Ограничения:**

- Это реконструкция выбранного авторского корпуса, а не универсальный импорт произвольного BLEND.
- Для реальных NEMA 17 стык запястья расширен на 16.6 мм; ось основания поднята на 10 мм с компенсацией первого вертикального звена. Высоты остальных осей сохранены.
- Наружные цилиндры приводов увеличиваются ради толщины каркаса, оболочки и доступных вставок. Пиксельное совпадение с непечатной заготовкой не заявляется.
- Внутренняя передача, её выходной носитель, полная гибкая проводка и динамика робота не выводятся из внешней формы. ReadyForManufacture=false.
- Режим фиксирует круглый профиль; параметры тонкости и скругления кассетного варианта в нём не применяются. Доступны диаметр звена, стенки, усиление и доля цветной крышки.

Исходники модуля: `src/RobotModel.cs`, `src/ProceduralBodyModel.cs`, `kernel/blender_enclosure.py`, `kernel/reference_enclosure.py`, `kernel/connected_body.py`.

## Числовые примеры

### rotary_static

Одна точечная нагрузка 0.5 кг на горизонтальном плече 300 мм, ось перпендикулярна плечу и тяжести; массы звеньев и внешние силы здесь намеренно равны нулю.

```json
{
  "input": {
    "mass_kg": 0.5,
    "lever_m": 0.3,
    "g": 9.81,
    "safety": 1.5,
    "motor_torque_Nm": 0.35,
    "reduction": 50,
    "efficiency": 0.7,
    "joint_speed_deg_s": 5
  },
  "expected": {
    "required_Nm": 2.20725,
    "available_Nm": 12.25,
    "motor_required_Nm": 0.06306428571428573,
    "motor_rpm": 41.66666666666667
  }
}
```

Это учебная проверка формулы, не итоговая нагрузка шестиосевого примера.

### offset_payload_53

Нагрузка 1 кг: от оси до конца родителя 100 мм, затем монтажное смещение дочернего шарнира ещё 500 мм по X. Вертикальный участок дочернего звена 20 мм не добавляет плечо тяжести вокруг Y. Другие массы в проверке обнулены.

```json

    "payload_kg": 1,
    "parent_end_x_mm": 100,
    "child_offset_x_mm": 500,
    "child_end_z_mm": 20,
    "g": 9.81,

  }

```

M_bound >= фактического момента; собственное мировое смещение корневой оси результата не меняет.

### gripper_tcp_54

Нулевая поза шестиосевого примера; масса всех деталей в контрольной проверке обнулена, груз 0.5 кг. Горизонтальный вылет последней кости 65 мм, фланец 10 мм, пальцы до TCP 64 мм.

```json
{
  "input": {
    "payload_kg": 0.5,
    "bone_x_mm": 65,
    "mount_mm": 10,
    "finger_tcp_mm": 64,
    "g": 9.81,
    "safety": 1.5
  },
  "expected": {
    "lever_m": 0.139,
    "shoulder_required_Nm": 1.0226925000000002

```

Проверка учитывает груз на пальцах, а не на более близком запястье. Моменты от собственной массы настоящей сборки добавляются отдельно.

## Актуальность описания

Сверено с исходниками выпуска 5.5.0, генератор `gearlab-blender-elbow-2` / `blender-elbow-2`. В `source_snapshot` основного JSON записаны SHA-256 использованных файлов: после изменения кода формулы и описание нужно проверить заново.

Справочник описывает существующую программу. Он не включает ещё не реализованные возможности из пожеланий и не является допуском к изготовлению робота.
