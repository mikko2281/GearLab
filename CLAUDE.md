# GearLab — начать отсюда

Это самостоятельная рабочая копия исходников GearLab 6.9.1, подготовленная для совместной работы пользователя, Codex и Claude. Дата комплекта: 14 ноября 2026 года.

## В каком порядке читать

1. [AGENTS.md](AGENTS.md) — правила версий и инженерные ограничения.
2. [ДЕРЕВО_ОБНОВЛЕНИЙ.md](ДЕРЕВО_ОБНОВЛЕНИЙ.md) — последовательность изменений, коммиты и карта файлов.
3. Запись нужной версии в [docs/updates](docs/updates), затем указанные функции и точный diff.
4. [Отчёт 6.9.1](docs/verification/6.9.1/README.md), [общий корпус](docs/COMPOUND_REDUCER.md), [материалы и нагрузки](docs/MATERIALS_AND_LOADS.md).

## Какая версия передана

- Кодовая база: `715f4c574e4d666f70f5c2028b870fe31dbb7afb`, локальный тег `v6.9.1-compound-animation-preview`, версия EXE `6.9.1.0`.
- В этой копии дополнительно оформлены документы передачи. Они не изменяют программу и не являются новым выпуском EXE.
- Готовая программа находится рядом: `../01_Готовая_программа/GearLab.exe`; `PTK.cmd` открывает проверенный пример ПТК → планетарный.
- `.git` содержит настоящую историю. В этой копии `core.autocrlf=false`, а `.git/info/attributes` учитывает историческую смесь LF/CRLF отдельно по файлам: это предотвращает ложный diff исходников. Рабочие исходники побайтно сверены с манифестом проверенной сборки; массовая нормализация строк не выполнялась. `origin` указывает на исходный локальный репозиторий на этом компьютере. Комплект не публикует изменения в GitHub и не меняет его состояние.
- Номера старых локальных preview могут совпадать с номерами иной ветки Claude. При сравнении ориентироваться на коммит, ветку и содержимое, а не только на номер.

## Сборка без загрузки зависимостей

Запускать PowerShell из корня этой папки:

```powershell
.\src\build.ps1 -OutputFolder Windows-dev
$env:GEARLAB_PROFILE_DIR = Join-Path $PWD 'test-results\profile-dev'
.\test.ps1 -NoBuild -OutputFolder Windows-dev -ResultsFolder test-results\dev -Suites shared-ptk,compound,compound-ui,overload,overload-ui,train60,robot-transmission60,upgrade62,viewer -SkipProceduralKernel
.\runtime\python.exe -B -X utf8 -I .\tools\test_shared_ptk_native.py test-results\dev\shared-ptk
node .\tools\test_scene_intro.mjs
node --experimental-vm-modules .\tools\test_web_preferences672.mjs
```

Компилятор берётся из установленного Windows .NET Framework 4.x. `runtime/`, `web/vendor/`, DLL WebView2 и распакованные примеры уже вложены как локальные зависимости/кэши; Git намеренно их игнорирует. Для двух JS-проверок нужен установленный Node.js. Команды native-аудита и полного `test.ps1` могут работать существенно дольше обычной сборки. Для изменений процедурного робота дополнительно запускать соответствующие наборы из `tools/test_robot.ps1`; пропуск процедурного ядра выше не означает, что его можно пропускать при изменении этого генератора.

## Как продолжать дерево обновлений

Перед правками проверить `git status`, создать отдельную рабочую ветку от этой базы, учитывать уже внесённые изменения пользователя. Не заменять существующие опубликованные теги, EXE и архивы.

Для следующего обновления создать запись по [шаблону](docs/updates/TEMPLATE.md), добавить её в корневое дерево и `docs/updates/index.json`. В записи указывать конкретную проблему, поведение до/после, файлы и функции, принцип изменения, тесты и их реальные результаты, ограничения, базовый и итоговый коммиты. Отделять проверенное от предположений и незавершённого. Если меняется программа, согласовать номер в интерфейсе, AssemblyInfo, документации и новом архиве по правилам AGENTS.md. Документирование комплекта не повышает версию приложения само по себе.

Конструкция предварительная: `ReadyForManufacture=false`. Не выдавать красивую анимацию, игровой Blender-меш, геометрический аудит или теоретический момент за изготовленный и испытанный механизм. Рабочая кривая момента NEMA17 пока не предоставлена.
